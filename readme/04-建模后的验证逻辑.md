# 04 - 建模后的验证逻辑

## 结论

**有验证处理，但不是常见的「训练集/测试集分类准确率（Accuracy）」那一套。**

脚本在建模之后做了 **Bootstrap 内部验证、校准曲线、C-index 和 ROC/AUC**，属于 **模型判别能力 + 校准度** 的评估；**没有** 独立测试集、交叉验证，也 **没有** 多分类混淆矩阵或整体分类准确率。

---

## 脚本整体逻辑（建模 → 验证）

```
数据预处理
    ↓
polr 有序逻辑回归
    ↓
p 值 + Brant 比例优势检验
    ↓
na.omit → rms::lrm 主模型 rms_model
    ↓
列线图 nomogram
    ↓
Bootstrap validate → C-index
    ↓
Bootstrap calibrate → 校准曲线
    ↓
样本内 ROC / AUC → 多阈值 AUC 循环 → Bootstrap AUC 置信区间
```

主验证对象是 **`rms_model`**（`lrm` 模型），前面的 `polr` / `model1` 更偏探索与假设检验。

---

## 建模后具体做了哪些「验证」

### 1. Bootstrap 内部验证（判别能力）

```r
validate_boot <- validate(rms_model, method = "boot", B = 1000)
corrected_cindex <- validate_boot["Dxy", "index.corrected"]/2 + 0.5
```

| 项目 | 说明 |
|------|------|
| 方法 | `rms::validate()`，Bootstrap 1000 次 |
| 指标 | **Optimism-corrected C-index**（由 Dxy 换算） |
| 含义 | 衡量模型对有序结局的 **排序/判别能力**，并校正过拟合乐观偏差 |
| 是否独立测试集 | **否**，仍在同一批 `clean_data` 上做内部验证 |

这 **不是** Accuracy，而是有序模型里更常用的 **一致性指数（C-index）**。

---

### 2. 校准度验证（预测概率是否靠谱）

```r
calibration <- calibrate(rms_model, method = "boot", B = 1000)
plot(calibration)
```

| 项目 | 说明 |
|------|------|
| 方法 | `rms::calibrate()`，Bootstrap 1000 次 |
| 输出 | 校准曲线图 |
| 含义 | 看 **预测概率** 与 **实际观测频率** 是否一致 |
| 是否准确率 | **否**，评的是校准，不是「猜对几类」 |

---

### 3. ROC / AUC（样本内判别能力）

```r
pred_probs <- predict(rms_model, type = "fitted")
binary_outcome <- as.numeric(clean_data$抑郁等级 > min(depression_levels))
roc_obj <- roc(binary_outcome, pred_probs)
```

以及多阈值循环（≥轻度、≥中度、≥重度）：

```r
for(i in seq_along(thresholds)) {
  binary_outcome <- as.numeric(clean_data$抑郁等级 >= thresholds[i])
  roc_obj <- roc(binary_outcome, pred_probs, quiet = TRUE)
  ci <- ci.auc(roc_obj, method = "bootstrap", boot.n = 2000)
}
```

| 项目 | 说明 |
|------|------|
| 做法 | 把 4 级有序结局 **二值化**，再算 ROC/AUC |
| 指标 | AUC + Bootstrap 95% CI |
| 是否独立测试集 | **否**，预测与真实标签都来自 **同一训练数据**（in-sample） |
| 是否准确率 | **否**，是 AUC，不是分类正确率 |

---

### 4. Bootstrap AUC 置信区间（重复实现，且有 bug）

脚本意图是用 Bootstrap 估计 AUC 的稳定性，但存在重复、残缺的代码块，以及再次定义的 `boot_auc` **并未真正执行完整个 Bootstrap 流程**。

## 建模前/旁的「检验」（不算准确率验证）

| 步骤 | 性质 |
|------|------|
| `brant(model)` | 检验 **比例优势假设** 是否成立，是模型前提检验 |
| 手动算 `polr` 的 p 值 | 变量 **显著性**，不是预测准确率 |
| `predprob` / `nom_pred` 函数 | 预测工具函数，本身不做验证 |

---

## 脚本 **没有** 做的验证

| 缺失项 | 说明 |
|--------|------|
| 训练集 / 测试集划分 | 虽加载了 `caret`，但 **未使用** |
| 交叉验证（k-fold） | 无 |
| 外部验证集 | 无 |
| 混淆矩阵 | 无 |
| 分类准确率 Accuracy | 无 |
| 多分类 F1 / Kappa 等 | 无 |
| 按「预测等级 vs 真实等级」算正确率 | 无 |

## 总结对照

| 问题 | 答案 |
|------|------|
| 建模后有没有验证？ | **有** |
| 是不是「准确率验证」？ | **不完全是**；主要是 **C-index、校准曲线、ROC/AUC** |
| 有没有独立测试集？ | **没有**，几乎全是 **同数据内部验证 / 样本内评估** |
| 方法学上是否合理？ | 有序逻辑回归用 C-index + 校准 + Bootstrap 校正 **方向正确**；但缺 hold-out 或外部验证 |
| 能否完整跑通验证部分？ | **部分不能**（`pred_scores` 未定义；部分代码残缺） |

---

## 简要评价

脚本 **设计上** 在建模后做了较完整的 **内部验证框架**：

1. **判别能力**：Bootstrap 校正 C-index、ROC/AUC
2. **校准度**：Bootstrap 校准曲线

但若问的是「模型预测对了多少」（Accuracy / 混淆矩阵 / 测试集表现），**脚本没有直接给出**；需要额外补充训练/测试划分、混淆矩阵、Accuracy 或线性加权 Kappa 等指标。
